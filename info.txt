# Research Assistant Codebase Information

This document provides detailed information about each file in the Research Assistant codebase and their responsibilities.

## Root Level Files

### Configuration & Setup Files

**pyproject.toml**
- Modern Python package configuration file using UV package manager
- Defines project dependencies including Django, FAISS, PyPDF, Together AI, etc.
- Specifies Python 3.13+ requirement and custom PyTorch CPU index
- Used by UV for dependency resolution and virtual environment management

**uv.lock**
- Lock file generated by UV package manager
- Contains exact versions of all dependencies and their sub-dependencies
- Ensures reproducible builds across different environments

### Django Management Files

**manage.py**
- Django's command-line utility for administrative tasks
- Entry point for running Django management commands
- Sets DJANGO_SETTINGS_MODULE to 'ai_notebook.settings'
- Used for migrations, running server, creating users, etc.

**startup.py**
- Comprehensive initialization script for the application
- Runs Django migrations and creates database tables
- Creates projects directory structure
- Can optionally open browser after server starts
- One-stop script for setting up and running the application

### Utility Scripts

**create_admin.py**
- Creates Django admin superuser if it doesn't exist
- Sets username 'admin' with password 'admin'
- Used for initial setup and ensuring admin access
- Safe to run multiple times (checks if user exists)

### Core Application Files

**doctoembed.py**
- Document processing and embedding engine
- Extracts text from PDF files using PyPDF
- Creates text chunks with overlap for better context
- Generates embeddings using SentenceTransformers
- Builds and manages FAISS vector indices
- Provides document search and similarity functions
- Core engine for document analysis and retrieval

**model.py**
- AI model integration layer using Together AI API
- Interfaces with DeepSeek-R1-Distill-Llama-70B model
- Handles token estimation and context truncation
- Manages API calls with error handling and response processing
- Provides query processing with document context
- Includes progressive summarization capabilities

### Static Files

**LICENSE**
- MIT License file defining usage terms and conditions

**README.md**
- Comprehensive project documentation
- Installation and setup instructions
- Feature overview and usage examples
- Project structure and configuration details

**changes.txt**
- Development changelog tracking modifications and updates

## Django Project Structure

### ai_notebook/ (Django Project Directory)

**ai_notebook/__init__.py**
- Python package initialization file
- Makes the directory a Python package

**ai_notebook/settings.py**
- Main Django configuration file
- Database settings (SQLite default)
- Static files configuration
- Authentication settings
- CORS configuration for API access
- Template engine configuration
- Security settings for production
- Custom settings for document storage paths

**ai_notebook/urls.py**
- Main URL routing configuration
- Includes document_qa app URLs
- Configures admin interface access
- Sets up static file serving for development

**ai_notebook/wsgi.py**
- WSGI (Web Server Gateway Interface) configuration
- Entry point for production web servers
- Connects Django to web server

**ai_notebook/asgi.py**
- ASGI (Asynchronous Server Gateway Interface) configuration
- For asynchronous web servers and WebSocket support
- Future-proofing for real-time features

### document_qa/ (Django App Directory)

**document_qa/__init__.py**
- Python package initialization file

**document_qa/apps.py**
- Django app configuration
- Defines app name and default auto field type

**document_qa/admin.py**
- Django admin interface configuration
- Currently minimal but can be extended for model management

**document_qa/models.py**
- Django ORM models for database schema
- Project model: stores project metadata and user ownership
- Source model: tracks uploaded documents per project
- Includes JSON serialization methods for API compatibility

**document_qa/views.py**
- Main application logic and API endpoints
- Authentication views (login, logout, register)
- Project management APIs (CRUD operations)
- Document upload and processing endpoints
- Question answering and summarization APIs
- User profile and settings management
- Model inference and health check endpoints

**document_qa/urls.py**
- URL routing for the document_qa app
- Maps URLs to view functions
- Includes API endpoints and HTML page routes
- Handles authentication and project-specific URLs

**document_qa/document_qa.py**
- Core document processing business logic
- DocumentQA class for managing project-specific operations
- Project folder management utilities
- Document indexing and querying functions
- Integration between Django models and document processing

### Database Migrations

**document_qa/migrations/__init__.py**
- Python package initialization for migrations

**document_qa/migrations/0001_initial.py**
- Initial database migration
- Creates Project and Source models
- Defines database schema structure

**document_qa/migrations/0002_project_user.py**
- Adds user foreign key to Project model
- Enables user-specific project ownership
- Data migration for user association

## Key Features and Responsibilities

### Document Processing Pipeline
1. **PDF Upload**: Users upload PDF documents through web interface
2. **Text Extraction**: doctoembed.py extracts text using PyPDF
3. **Chunking**: Text is split into overlapping chunks for better context
4. **Embedding**: SentenceTransformers creates vector embeddings
5. **Indexing**: FAISS builds searchable vector index
6. **Storage**: Metadata and indices stored per project

### AI Integration
1. **Together AI**: model.py interfaces with DeepSeek-R1 model
2. **Context Management**: Handles token limits and context truncation
3. **Query Processing**: Combines document context with user questions
4. **Response Generation**: AI-powered answers and summaries

### User Management
1. **Authentication**: Django-based login/logout/registration
2. **Project Ownership**: Users can only access their own projects
3. **Admin Interface**: Django admin for user and project management

### API Architecture
1. **RESTful APIs**: JSON-based API endpoints for all operations
2. **CSRF Protection**: Security for state-changing operations
3. **CORS Support**: Cross-origin resource sharing for frontend
4. **Error Handling**: Comprehensive error responses and logging

### Deployment Support
1. **Static File Management**: Proper handling of CSS/JS/images
2. **Database Migrations**: Automatic schema management
3. **Environment Configuration**: Development vs production settings

This architecture provides a scalable, secure, and user-friendly document analysis system with modern web technologies and AI capabilities.
